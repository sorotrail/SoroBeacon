# Releasing & Reproducible Builds

SoroBeacon builds its release binaries (`sorobeacon` and `terraform-provider-sorobeacon`) deterministically so any operator or auditor can compile a tagged commit from source and verify that the resulting binary is **byte-for-byte identical** to the published artifact.

---

## How Deterministic Builds Work

Every release build (and `make build` / `make build-tf` / `Dockerfile`) enforces four invariants:

1. **Path-independent compilation (`-trimpath -buildvcs=false`):**
   Strips the builder's local checkout path (`/home/runner/...`, `/Users/...`) from DWARF/stack metadata and omits host git worktree status from the Go build info header.
2. **Deterministic linker output (`-ldflags "-s -w -buildid="`):**
   Clears the Go toolchain's path-derived build ID (`-buildid=`) and symbol/debug tables while preserving Go runtime stack traces and `go version -m` module metadata.
3. **Static linking (`CGO_ENABLED=0`):**
   Eliminates host libc (`glibc` / `musl`) and system C compiler (`gcc` / `clang`) variance across build machines.
4. **Commit-derived timestamp (`SOURCE_DATE_EPOCH` / `git show`):**
   Instead of reading the wall clock (`date -u`), the build timestamp injected into `internal/buildinfo.Date` (and served by `GET /api/v1/version`) is derived in UTC from the commit's timestamp:
   ```sh
   DATE=$(TZ=UTC git show -s --format=%cd --date=format-local:%Y-%m-%dT%H:%M:%SZ HEAD)
   ```
   `/api/v1/version` therefore still reports the exact release `version`, `commit`, and `build_date`, and two builders in different timezones or on different days produce the exact same bytes.

## Verifying a Release Binary Locally

To reproduce a release binary for tag `<TAG>` (for example `v0.1.0`) and compare its SHA-256 digest:

### 1. Check out the exact tag and match the Go toolchain version

Check `go.mod` (or run `go version -m <release-binary>`) for the Go version used to build the release, then run:

```sh
git checkout <TAG>

VERSION=$(git describe --tags --always --dirty)
COMMIT=$(git rev-parse --short=12 HEAD)
DATE=$(TZ=UTC git show -s --format=%cd --date=format-local:%Y-%m-%dT%H:%M:%SZ HEAD)

CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -buildvcs=false \
  -ldflags "-s -w -buildid= -X github.com/sorotrail/sorobeacon/internal/buildinfo.Version=${VERSION} -X github.com/sorotrail/sorobeacon/internal/buildinfo.Commit=${COMMIT} -X github.com/sorotrail/sorobeacon/internal/buildinfo.Date=${DATE}" \
  -o bin/sorobeacon ./cmd/sorobeacon

sha256sum bin/sorobeacon
```

Or run the automated two-environment reproducibility check directly:

```sh
make verify-reproducible
```

`make verify-reproducible` (`./scripts/verify-reproducible-build.sh`) exports `HEAD` into two separate directory trees of different depths with distinct `HOME`, `USER`, `HOSTNAME`, `TZ` (`UTC` vs `America/New_York`), `TMPDIR`, and `GOCACHE`, builds both `sorobeacon` and `terraform-provider-sorobeacon`, verifies that `Version`, `Commit`, and `Date` are stamped into `sorobeacon`, and asserts identical SHA-256 digests.

## Continuous Integration Gate

The `reproducible-build` job in [`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs `./scripts/verify-reproducible-build.sh` on every pull request and push to `main`. If a change introduces host-dependent bytes into either binary, the job fails and prints:

1. File sizes and SHA-256 digests of both builds.
2. A unified diff of `go version -m` embedded build metadata.
3. A unified diff of ELF section headers (`objdump -h`).
4. The first 40 differing byte offsets (`cmp -l`).

## What Is Covered (and What Is Not)

- **Covered (byte-for-byte identical):**
  - `sorobeacon` binary (`./cmd/sorobeacon`)
  - `terraform-provider-sorobeacon` binary (`./terraform-provider-sorobeacon`)
  - The `/usr/local/bin/sorobeacon` binary inside the container image when built with identical `VERSION`, `COMMIT`, and commit-derived `DATE` build arguments.
- **Not covered without OCI layer timestamp rewriting:**
  - While the `/usr/local/bin/sorobeacon` binary inside the Docker image is byte-for-byte reproducible, OCI image layer tarballs generated by a plain `docker build` record filesystem modification times unless built with BuildKit's `rewrite-timestamp=true` and `SOURCE_DATE_EPOCH`. To verify a container image, extract `/usr/local/bin/sorobeacon` from the image and compare its SHA-256 digest against a local `make build` of the same commit.
